# Kararlar

Biçim: `Dn — karar — gerekçe / kaynak`

- **D1 — Android uygulaması sıfırdan yazılır.** — Kullanıcı kararı (2026-09-25). `kamp-sag-` ve `kamp-sagiweb` yalnızca referans.
- **D2 — Kimlik doğrulama Supabase Auth.** — Kullanıcı kararı (2026-09-25); Bölüm 0.5'teki "Firebase Authentication" şartının yerine geçer.
- **D3 — AI sağlayıcı OpenAI (analiz + embedding), yalnızca backend üzerinden.** — Kullanıcı kararı (2026-09-25); Bölüm 0.8/0.9'daki "Gemini" şartının yerine geçer. Anahtar Edge Function secret'ıdır.
- **D4 — Kod yazım desenleri `whered-d-put` projesinden alınır** (config ortamdan, yapılandırılmamış build "bağlı değil" ekranı gösterir, `AppError`/`AppResult`/`safeCall`, CI ile build doğrulama). — Kullanıcı talebi (2026-09-25).
- **D5 — Build doğrulaması GitHub Actions'ta.** — Bu cloud ortamı Android SDK'yı (`dl.google.com`) indiremiyor; CI indirebiliyor.
- **D6 — Hesap yaşam döngüsü `profiles.account_status`:** `PROFILE_INCOMPLETE → DOCUMENT_REQUIRED → PENDING_REVIEW → APPROVED | REJECTED`, ayrıca `SUSPENDED`. Yalnızca backend değiştirir; istemcinin `profiles` tablosuna yazma politikası yoktur, profil `complete_profile` RPC'siyle yazılır.
- **D7 — Profil bilgileri doğrulama başladıktan sonra kilitlenir** (`profile_locked`). — Belge bu bilgilere göre onaylanır; onay sonrası üniversite değişirse doğrulama anlamsızlaşır.
- **D8 — Üniversite listesi veritabanından gelir, uygulamaya gömülü değildir** (Bölüm 0.15). Kaynak: ürün sahibinin verdiği `supabase/data/province-universities.json` (81 il, 206 kurum). `scripts/generate-universities-migration.py` bu dosyadan migration üretir; yalnızca ad, il ve website domain'i yüklenir (iletişim bilgisi ve rektör adı yüklenmez). Liste değişirse JSON güncellenir ve yeni bir migration üretilir; migration upsert olduğu için tekrar çalıştırılabilir.
- **D9 — Paket adı `com.kampusagi.android`.** — Play'de kalıcıdır; kullanıcı farklı bir paket adı isterse ilk yayından ÖNCE değiştirilmelidir.
- **D10 — Yönetici yetkisi `auth.users.raw_app_meta_data.role = 'admin'`** (JWT `app_metadata`). Bu alanı yalnızca service role yazabilir; kullanıcı kendini admin yapamaz. Uygulama bu bilgiyi yalnızca ekranda ne gösterileceğine karar vermek için okur; her admin işlemi veritabanında `is_admin()` ile yeniden doğrulanır. İlk admin Supabase Dashboard'dan (Authentication → kullanıcı → app_metadata) veya service role ile atanır.
- **D11 — Öğrenci belgesi akışı:** istemci PDF'i `student-documents/<uid>/<uuid>.pdf` yoluna yükler (Storage RLS: yalnızca kendi klasörü, yalnızca `DOCUMENT_REQUIRED`/`REJECTED` durumunda), ardından `submit-student-document` Edge Function'ı dosyanın gerçekten PDF olduğunu ve 10 MB sınırını baytlardan doğrular (geçersizse siler), kaydı service role ile `submit_student_document()` üzerinden açar. Yüklenen belge silinemez/değiştirilemez (inceleme kanıtı). Reddedilen kullanıcı profilini düzeltip yeniden yükleyebilir.
- **D12 — Admin belgeyi imzalı URL yerine uygulama içi önbellekten açar** (`FileProvider`, tek sabit dosya adı). Paylaşılabilir bir bağlantı üretilmez.
- **D13 — Alt gezinme çubuğunda yalnızca uçtan uca çalışan özelliklerin sekmesi bulunur** (Bölüm 0.22). Şu an: Topluluk, Profil. İhtiyaç, Eşleşmeler ve Sohbet ilgili fazlar tamamlanınca eklenir; boş/"yakında" sekmesi yoktur.
- **D14 — Topluluk görünürlüğü:** GENEL gönderiler tüm onaylı öğrencilere, ÜNİVERSİTEM gönderileri yalnızca aynı üniversitedeki onaylı öğrencilere görünür. Okuma dahil her işlem `APPROVED` hesap ister. Yazar, üniversite ve sayaçlar sunucuda atanır; gönderi/yorum silme yumuşaktır (`deleted_at`), hesap silinince CASCADE ile gider. Hız sınırı: saatte 10 gönderi, 60 yorum.
- **D15 — OpenAI yalnızca Edge Function'lardan çağrılır; model adları koda gömülü değildir.** `OPENAI_API_KEY`, `OPENAI_CHAT_MODEL`, `OPENAI_EMBEDDING_MODEL` Edge Function secret'larıdır; biri eksikse fonksiyon `503 ai_not_configured` döner, uygulama bunu açıkça söyler (tahmini model/sahte analiz yok). Embedding boyutu 1536'dır (tablo `vector(1536)`); istekte `dimensions: 1536` gönderilir, farklı boyut dönerse kayıt reddedilir.
- **D16 — Yapay zekâ çıktısına güvenilmez:** OpenAI strict JSON şemasıyla çağrılır, çıktı sunucuda `normalizeDraft` ile yeniden doğrulanır, veritabanı aynı sınırları CHECK ile tekrar uygular. Öğrenci taslağı yayınlamadan önce görür ve düzenler.
- **D17 — Yapay zekâ kotası:** onaylı öğrenci başına 24 saatte 30 analiz ve 10 yayın (`ai_usage`, `consume_ai_quota`, eşzamanlı çağrılar advisory lock ile sıralanır); kişi başına en fazla 20 aktif ilan.
- **D18 — Eşleşme skoru gerçek pgvector kosinüs benzerliğidir:** `score = round(100 * (1 - cosine_distance))`, doğrudan `find_matches()` sonucundan gelir; istemci skor üretmez. Adaylar: aynı üniversite, `ACTIVE`, onaylı sahip, kendi ilanı değil, mesafe ≤ 0,5 (benzerlik ≥ %50). Eşik altı ilanlar "eşleşme" olarak gösterilmez.
- **D19 — Sohbet alındıları gerçek veriden gelir:** "Gönderildi" = mesaj sunucuda kayıtlı; "Okundu" = karşı üyenin `last_read_at` değeri mesaj zamanına ulaştı. "Gönderiliyor/Gönderilemedi" yalnızca henüz sunucuya ulaşmamış yerel mesajlar içindir. Mesaj kimliğini istemci üretir; yeniden deneme aynı kimlikle yapılır, sunucuda çift kayıt oluşmaz.
- **D20 — Gerçek zamanlı güncelleme Supabase Realtime (postgres changes) ile, sinyal olarak kullanılır:** değişiklik gelince ekran sohbeti RPC ile yeniden okur. Realtime olayları RLS ile yalnızca sohbet üyelerine gider. "Yazıyor" ve "çevrimiçi" göstergeleri bu fazda yoktur (uydurma durum gösterilmez).
- **D21 — Sohbet yalnızca onaylı öğrenciler arasında; kişi çifti başına tek sohbet; dakikada 30 mesaj sınırı; askıya alınan/doğrulaması düşen kişiye mesaj gönderilemez.**
